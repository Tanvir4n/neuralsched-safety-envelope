The problem

SmartPack (GNN + PPO) is a powerful new scheduler — but unproven. Letting it place real jobs on day one is a risk. The challenge: wrap it in a safety layer.

  • Safety Envelope — hard limits it may never break: max node temperature & max job wait. Breaking actions are rejected.
  • Shadow Test — run it beside FIFO on the same jobs, compare completion & failures — without applying its choice.
  • Blocked Log — every rejected action in one sentence naming the limit it broke.
The core design choice

"SmartPack runs in shadow mode. It must prove itself before it controls real jobs."

FIFOis the only executor — it places every real job, no exceptions. SmartPackis observed, never obeyed — its choice is scored, then thrown away.

How one job flows

Job arrives
real or simulated → SmartPack
hypothetical → Envelope check
temp? wait? → Blocked log
if it breaks a limit
FIFO places the real job  →  cluster actually runs it

The agent's path never touches the cluster. Only FIFO's path does.

Live, visible & honest

  • Live-adjustable limits — drag a slider to tighten a rule and watch blocks climb in real time.
  • "Force a block" button — guarantees a rejection on demand for the demo.
  • Real + synthetic jobs feed the test; every synthetic job is flagged simulated so nothing is faked as real load.
  • All of it shown on a dedicated Safety dashboard page — nothing hidden in the background.

Demo — verify it in 5 steps

  • 1. Open the Safety page — two scoreboards; only the agent has a "Blocked" count.
  • 2. Submit a real job → response reads "Placed by FIFO (agent ran in shadow)."
  • 3. Click Force a block → a red one-sentence entry appears in the log.
  • 4. Drag the temperature slider down → blocked count rises live.
  • 5. Scroll the Blocked Log — each line names the exact limit broken.

Scripted end-to-end run: 16 / 16 checks passing against the live API.
